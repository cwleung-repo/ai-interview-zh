吞吐 roofline

交互tokens/s = batch / max(带宽时间, 算力时间)

decode 每步要把权重读一遍：小 batch 时吞吐随 batch 近似线性增长；只有模型与 batch 都足够大，才会转向算力受限。拖动 batch 与带宽，看拐点在哪。

峰值算力按 BF16 990 / FP8 1979 TFLOPS；INT4 权重仍以 BF16 计算，不提高算力峰值，只降带宽。忽略 kernel 效率与网络开销。

怎么读

  • 小 batch 时吞吐随 batch 近似线性增长；70B 在 2k 上下文下到 batch 512 仍是带宽受限。
  • 70B bf16、3.35 TB/s 的理论上限约 24 token/s；量化到 INT4 后约翻四倍。
  • 405B 才会在 batch≈360 之后切到算力受限；70B 的 KV 读取随 batch 线性增长，看不到拐点。
