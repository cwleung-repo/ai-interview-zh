答案

展开简短答案

多 agent 通常是一个 orchestrator 拆任务、若干 worker 并行/串行执行、再汇总。它在任务可清晰分解、子任务相互独立、且单 agent 上下文装不下时有效；在需要紧密共享状态、强一致性、或子任务高度耦合时会崩——通信开销和错误传播会吃掉收益。

展开完整答案（要点）
  • 常见拓扑：supervisor（中心调度）、handoff（转交）、debate（多视角）、pipeline（流水线）。
  • 崩溃点：上下文不同步、重复劳动、互相等待、错误被层层放大、成本随 agent 数线性上升。
  • 判断标准：子任务能否用明确契约（输入/输出 schema）隔离；不能就别拆。
  • 工程：共享黑板/文件系统、明确的终止条件、每个 agent 的预算与超时。
