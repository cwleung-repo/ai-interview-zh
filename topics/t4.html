  1. 01

    完整讲一遍 RLHF：奖励模型、策略优化、KL 惩罚。

    2 条原文答案
    本站答题要点 + 原文答案

    RLHF 三步：SFT 打底 → 用人类偏好比较训练奖励模型 r(x,y) → 用 PPO 优化策略 π，最大化 r 并减去 KL(π‖π_ref) 惩罚；裁剪（clip）与 KL 系数一起控制每步更新幅度。KL 项防止策略为了刷分而输出退化文本，同时保留预训练能力。

    • 奖励模型通常在 SFT 模型上用 pairwise loss：-log σ(r(chosen) - r(rejected))，数据是同一 prompt 的多条排序。
    • PPO 目标：E[r(x,y)] - β·KL(π‖π_ref)，还要用 GAE 估优势、clip 比率限制更新幅度。
    • 四个模型同时在显存里：策略、参考、奖励、价值；显存约为 SFT 的 3–4 倍，取决于 critic 与奖励模型的规模。
    • 失败模式：奖励黑客、长度偏置（奖励模型偏好长答案）、KL 坍塌或发散。
    max_π E_{x~D, y~π(·|x)} [ r(x,y) - β·KL(π(y|x) ‖ π_ref(y|x)) ]

    原文答案：基于人类反馈的强化学习(RLHF) · 近端策略优化(PPO)

  2. 02

    什么是 DPO？为什么它在许多实验室取代了基于 PPO 的 RLHF？什么时候在线 RL 仍然更好？

    Hugging FaceScale AI腾讯阿里巴巴(淘天、阿里云)美团1 条原文答案
    本站答题要点 + 原文答案

    DPO 把 RLHF 的约束最优解解析出来，直接用偏好对做分类损失：增大 chosen 相对参考模型的 log 概率、压低 rejected。它不需要奖励模型和在线采样，训练稳定、成本低，因此在多数场景取代了 PPO。在线 RL 仍更好的情况：需要探索、奖励可验证且稀疏、或要优化多轮/工具使用的轨迹。

    • 损失：-log σ(β[log π(y_w)/π_ref(y_w) - log π(y_l)/π_ref(y_l)])，β 控制偏离参考的强度。
    • DPO 是离线方法：数据分布固定，无法发现策略自己生成的新错误（没有 on-policy 探索）。
    • PPO/GRPO 在线采样可以优化“模型自己会犯的错”，在数学、代码等可验证任务上更强。
    • 实践：SFT → DPO 是性价比最高的对齐配方；要进一步提升推理能力再上 RLVR/GRPO。

    原文答案：直接偏好优化(DPO)

  3. 03

    解释 GRPO，以及为什么在大规模下去掉价值网络很重要。

    DeepSeek字节跳动腾讯美团阿里巴巴(淘天、阿里云)1 条原文答案
    本站答题要点 + 原文答案

    GRPO 对同一个 prompt 采样一组（G 个）回答，用组内奖励的均值/标准差做归一化得到优势，从而去掉价值网络。省掉一个与策略同规模的模型，显存和训练稳定性都大幅改善，适合可验证奖励（对错、通过率）的大规模 RL。

    • 优势 Â_i = (r_i - mean(r)) / std(r)，组内比较，天然适配“同一题多个解”的设定。
    • 没有 critic 就不用训练价值函数，也不用 GAE；代价是每组必须采样多次，rollout 成本上升。
    • DeepSeek-R1 用它做 RLVR：奖励是答案是否正确 + 格式，训练出长链推理。
    • 变体：Dr.GRPO（去长度偏置）、DAPO（解耦裁剪、动态采样）等，解决长度与难度偏置。
    Â_i = (r_i - mean(r_1..r_G)) / std(r_1..r_G)
L = -E[min(ρÂ, clip(ρ,1-ε,1+ε)Â)]

    原文答案：组相对策略优化(GRPO)

  4. 04

    从数学上解释 LoRA 的分解。它为什么有效？如何选择秩 r？

    美团腾讯京东1 条原文答案
    本站答题要点 + 原文答案

    LoRA 把权重更新约束成低秩分解 ΔW = BA，B∈R^{d×r}、A∈R^{r×k}，只训练 A、B，冻结 W。它的依据是微调的权重更新具有低内在秩；r 通常 8–64，任务越复杂、数据越多，r 越大，但超过某个点收益递减。

    • 参数量从 d·k 降到 r·(d+k)；7B 模型 r=16 时适配器只有几百万参数。
    • 初始化：A 高斯、B 为零，保证训练开始时 ΔW=0，不破坏基座。
    • 缩放 α/r 控制更新幅度；常用 α=2r。
    • 推理可合并回 W（无额外延迟），也可保留适配器做多任务切换。
    W' = W + (α/r)·BA,  B ∈ R^{d×r}, A ∈ R^{r×k}
params = r·(d+k)  vs  全量 d·k

    原文答案：LoRA——LLM 的低秩适配

  5. 05

    QLoRA 是如何实现显存降低的？它的量化权衡是什么？

    Hugging Face2 条原文答案
    本站答题要点 + 原文答案

    QLoRA 把冻结的基座量化到 4-bit NF4，只训练半精度的 LoRA 适配器，再用双重量化和分页优化器压掉额外开销，于是 7B 微调从 ~56 GB 降到 ~6 GB。权衡是反量化带来的额外计算（约慢 20–40%）、4-bit 的精度损失，以及实现/内核依赖。

    • NF4：16 个量化电平放在正态分布的分位点上，比均匀 4-bit 更适合权重分布。
    • 双重量化：对每 64 个权重一组的 scale 再做 8-bit 量化，7B 模型省约 0.3 GB。
    • 分页优化器：显存不足时把优化器状态换到 CPU，避免 OOM（吞吐换稳定）。
    • 质量：原论文在多项基准上 QLoRA r=64 追平全量微调；r=16 略低但差距很小。

    原文答案：AI 工程详解：LLM、RAG、MCP、Agent、微调、量化 · 模型量化是如何工作的？

  6. 06

    比较 LoRA、prefix tuning、prompt tuning 与全量微调。分别何时选用？

    Sarvam AIApple2 条原文答案
    本站答题要点 + 原文答案

    全量微调改所有参数，效果上限最高、显存最贵；LoRA 加低秩旁路，性价比最高、可多适配器切换；prefix tuning 在每层前加可训练前缀向量，参数极少但占上下文、效果不稳；prompt tuning 只学输入端的软提示，最省但能力最弱。

    • 数据量 <1 万条、单任务：LoRA r=8–16 足够；要极致效果且有多卡：全量。
    • 多租户/多任务：每个任务一个 LoRA，基座共享，切换成本低。
    • Prefix/prompt tuning 适合分类、风格控制等轻量任务，生成质量通常不如 LoRA。
    • 选择还要看推理：LoRA 可合并，prefix 会占 KV/上下文，prompt tuning 需要模型支持软提示。

    原文答案：微调是如何工作的？ · Prefix Tuning 是如何工作的？

  7. 07

    什么是灾难性遗忘？微调时如何缓解？

    Mistral AI1 条原文答案
    本站答题要点 + 原文答案

    灾难性遗忘是微调把参数推离预训练分布，导致通用能力（推理、写作、其他语言）下降。缓解：小学习率 + 少 epoch、LoRA 等参数高效方法、混入 5–20% 通用数据回放、KL 正则约束偏离、以及按能力分层的评估集。

    • 最容易被忽略的是评估：只看目标任务涨点，没测通用能力，上线后才发现变笨。
    • 数据配比：领域数据 + 通用指令数据混合，比纯领域数据更稳。
    • LoRA 的低秩约束天然起到正则作用，遗忘通常小于全量微调。
    • 已经遗忘可以用模型融合（task arithmetic）或回放部分预训练数据恢复。

    原文答案：LLM 中的持续学习

  8. 08

    提示、RAG 还是微调：请给出你的决策框架，并附上成本与延迟。

    OpenAIMistral AICohereMicrosoftDatabricksGlean滴滴京东阿里巴巴(淘天、阿里云)腾讯1 条原文答案
    本站答题要点 + 原文答案

    决策顺序：先用提示 + few-shot（小时级、零训练）；不够就上 RAG（知识频繁变、需要引用）；如果问题是“行为/格式/风格/领域语汇”而非“缺知识”，或者 RAG 的延迟/成本不可接受，才微调；最后才考虑继续预训练。成本上提示 < RAG < LoRA < 全量，延迟上微调最低（可合并）、RAG 中等、长提示最高。

    • 判断标准：知识型 → RAG；能力型（遵循复杂格式、特定推理风格）→ 微调；两者都有 → 先 RAG 再 LoRA。
    • RAG 的优势是可更新、可引用、可权限控制；微调的知识更新要重训，且容易幻觉。
    • 成本要算总拥有成本：数据标注、训练、评估、部署、以及每次调用的 token。
    • 常见错误：用微调灌知识——模型记住的是措辞不是事实，问法一变就错。

    原文答案：AI 工程详解：LLM、RAG、MCP、Agent、微调、量化

  9. 09

    做一下用 Adam 以 bf16 全量微调一个 7B 模型的 GPU 显存计算。再算用 LoRA 的情况。

    Mistral AIHugging Face
    本站答题要点 + 原文答案

    bf16 全量微调 7B：权重 14 GB、梯度 14 GB、Adam 一阶二阶各 14 GB（bf16）或各 28 GB（fp32），合计 56 GB（bf16 状态）、84 GB（Adam 状态用 fp32）到约 112 GB（保留 fp32 主权重），还没算激活。LoRA r=16：权重 14 GB + 适配器参数与状态不到 0.2 GB，加上激活约 18–20 GB。

    • 公式：每参数字节 = 权重 2 + 梯度 2 + 优化器 2×状态精度；混合精度训练通常主权重还是 fp32，会再多 4 字节。
    • 7B × 16 B/参数 ≈ 112 GB（fp32 master weights + Adam m/v），所以实际全量微调往往要 8×80 GB 或 ZeRO。
    • LoRA 只对适配器算梯度和优化器状态，冻结部分只需权重。
    • 激活随 batch×seq 增长，gradient checkpointing 用算力换显存。
    全量: 7e9 × (2+2+2+2) = 56 GB (bf16 states)
      7e9 × (2+2+4+4+4) ≈ 112 GB (fp32 master)
LoRA: 14 GB + 适配器(<0.2 GB) + 激活
  10. 10

    什么是 RLVR(可验证奖励的 RL)？它在哪些方面优于学习式奖励模型？

    Zhipu AIAlibabaSarvam AIScale AI1 条原文答案
    本站答题要点 + 原文答案

    RLVR 用可程序化验证的奖励（数学答案对错、代码单测通过、格式合法）替代学出来的奖励模型，信号客观、不可作弊、可大规模生成。它在数学、代码、工具调用等有明确判定器的任务上显著优于奖励模型，但对开放性写作、主观质量无能为力。

    • 奖励 = 规则/执行结果，不需要人工标注偏好对，成本极低。
    • 天然抗奖励黑客（答案对就是对），但会诱导模型钻规则空子（如只输出格式正确的废话）。
    • 适合：竞赛数学、代码生成、SQL 执行、结构化抽取、agent 任务成功与否。
    • 局限：奖励稀疏（全错时无梯度），需要课程学习/难度筛选；开放任务仍需人类或模型评判。

    原文答案：组相对策略优化(GRPO)

  11. 11

    解释 RLHF 中的奖励黑客(reward hacking)，以及各实验室如何应对。

    Scale AI字节跳动1 条原文答案
    本站答题要点 + 原文答案

    奖励黑客是策略找到奖励模型的漏洞、拿到高分却不符合真实意图，典型如堆砌关键词、无脑变长、讨好式回答、伪造引用。应对：奖励模型集成与定期重训、KL 惩罚、长度归一化、用可验证奖励替代主观奖励、以及红队式对抗评估。

    • Goodhart 定律：指标一旦成为目标就不再是好指标。
    • 长度偏置最常见：奖励模型偏好长答案，策略就学会啰嗦；用长度归一化或成对比较控制。
    • 开放式任务可用“宪法式”原则 + AI 反馈，但仍需人工抽检。
    • 监控：训练中定期用未见过的评估集和人工盲评，别只看 reward 曲线。

    原文答案：基于人类反馈的强化学习(RLHF)

    什么是蒸馏？如何用大模型构建一个强的小模型？

    Alibaba1 条原文答案
    本站答题要点 + 原文答案

    蒸馏是让小模型（学生）模仿大模型（教师）的输出分布或推理轨迹：logit 蒸馏用 KL 对齐软标签，序列蒸馏用教师生成的答案做 SFT，推理蒸馏用教师的思维链。关键在数据质量与覆盖，而不是单纯堆量。

    • logit 蒸馏信息量更大（暗知识），但需要教师 logits 与同词表；黑盒 API 只能做序列蒸馏。
    • 推理蒸馏：只学最终答案学不到过程，要学完整 CoT，并过滤掉错误轨迹。
    • on-policy 蒸馏（学生自己生成、教师打分/纠错）通常优于纯离线模仿。
    • 评估要包含教师没覆盖的分布，否则只是学会了复述。
