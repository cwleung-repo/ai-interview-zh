  1. 01

    设计一个面向 1000 万文档、带每用户权限的企业级 RAG 助手。

    OpenAIMicrosoftAmazonDatabricksScale AI字节跳动阿里巴巴(淘天、阿里云)
    本站答题要点 + 原文答案

    分层：文档接入（解析/分块/ACL 同步）→ 索引（向量 + 关键词 + 元数据）→ 检索（pre-filter + hybrid + rerank）→ 生成（引用 + 拒答）→ 服务（缓存、限流、trace）。每用户权限在检索前用 metadata filter 强制，10M 文档按租户/密级分片，索引增量更新。

    • 接入：连接器拉取文档与权限，解析成块，写入 ACL 字段（tenant_id、group_ids、classification），变更走 CDC。
    • 索引：向量库按 tenant 分区；ACL 用可过滤的字段；为高频过滤字段建倒排。
    • 检索：query 改写 → hybrid 召回 → ACL filter → rerank → 取 top 8，附带来源与更新时间。
    • 生成：要求逐句引用，证据不足时明确说“未找到”，并给出可点击的来源。
    • 非功能：p95 延迟、每租户 QPS、缓存（答案 + 前缀）、审计日志、删除传播。
  2. 02

    设计一个代码助手：仓库索引、上下文组装、编辑应用、评估。

    Cursor字节跳动腾讯美团阿里巴巴(淘天、阿里云)2 条原文答案
    本站答题要点 + 原文答案

    代码助手分四块：仓库索引（AST/符号 + 嵌入 + 依赖图）、上下文组装（当前文件 + 相关符号 + 检索片段 + 编辑历史）、编辑应用（结构化 diff/patch，校验语法与测试）、评估（单测通过率 + 人工接受率）。关键是“给出可应用的编辑”，而不是只聊天。

    • 索引：按函数/类切块，保留签名与 docstring；用 tree-sitter 做语法感知分块。
    • 上下文：优先光标附近与 import 图上的邻居，再补语义检索；控制 token 预算。
    • 编辑：让模型输出统一 diff 或 search/replace 块，服务端校验冲突后再落盘。
    • 评估：仓库级任务（修 bug、加测试）用单测通过率；交互指标看建议接受率与撤销率。

    原文答案：Cursor 是如何工作的？ · Claude Code 是如何工作的？

  3. 03

    设计一个能执行真实动作、并可升级到人工的客服 agent。

    消费级 ML 公司Sierra滴滴京东美团
    本站答题要点 + 原文答案

    客服 agent = 意图识别 + 知识检索 + 工具调用（查单/退款/改地址）+ 策略引擎（能不能做、要不要审批）+ 人工升级。所有写操作幂等并可撤销，高风险动作强制人工确认，失败时带着完整上下文转人工，而不是让用户重述。

    • 对话状态机：识别 → 澄清 → 执行 → 确认 → 关闭；每步记录结构化槽位。
    • 工具：查询类直接调，写入类走 prepare/commit 两阶段 + 幂等键。
    • 升级：置信度低、涉及金额超阈值、用户要求人工、或连续两次失败。
    • 质量：解决率、一次解决率、转人工率、CSAT、以及错误动作率。
  4. 04

    为大型商品目录设计语义搜索。

    Character.AI京东1 条原文答案
    本站答题要点 + 原文答案

    商品语义搜索 = 查询理解（品类/属性/意图）+ 多路召回（BM25、向量、类目导航、行为协同）+ 排序（相关性 + 业务目标）+ 多样化。关键是属性结构化与 query-product 对齐，纯向量搜不出“红色 32G 防水”这种组合约束。

    • 商品标题/属性/图片分别建索引；属性做规范化（颜色、尺码、容量）。
    • 查询解析出硬约束（品类、价格区间）做 filter，软意图（风格、场景）走向量。
    • 排序特征：文本相关性、类目匹配、销量、转化率、退货率、多样性惩罚。
    • 评估：离线 nDCG/recall，线上 CTR/CVR/零结果率。

    原文答案：语义搜索是如何工作的？

  5. 05

    设计一个结合分类器与 LLM 的内容审核系统。

    Meta
    本站答题要点 + 原文答案

    两级：便宜的分类器/规则处理高流量与明确违规（色情、暴力、垃圾广告），LLM 处理语义复杂、需要解释的案例（仇恨、隐晦诱导、上下文相关）；LLM 输出结构化判定 + 理由 + 置信度，低置信度转人工，并保留申诉通道。

    • 分类器：蒸馏的小模型，延迟毫秒级，负责召回大部分；LLM 负责难例与二审。
    • 策略：按风险分级（删除/限流/打标/放行），不同级别不同审核强度。
    • 一致性：给 LLM 明确 policy rubric 与 few-shot，定期用人工标注校准。
    • adversarial：用户会改写规避，需要持续更新样本与对抗训练。
  6. 06

    设计一个文档智能流水线：输入扫描版 PDF，输出结构化字段，规模 1000 万文档。

    Palantir
    本站答题要点 + 原文答案

    流水线：PDF 解析（版面分析 + OCR）→ 区域分类（表/图/正文/印章）→ 字段抽取（结构化 schema + LLM/规则）→ 校验（跨字段一致性、金额合计）→ 人工复核队列 → 落库。10M 规模靠批处理、去重、增量与失败重试。

    • 先做文档分类与路由，不同模板走不同抽取器，别用一个 prompt 打天下。
    • 表格用专用模型/库抽取，保留单元格坐标；扫描件质量差时先做图像增强。
    • 置信度低的字段进入人工复核，复核结果回流做训练数据。
    • 吞吐：按页计费与限流，任务队列 + 幂等 + 断点续跑。
  7. 07

    为拥有数千张表的数仓设计一个 Text-to-SQL 系统。

    DatabricksPalantir
    本站答题要点 + 原文答案

    Text-to-SQL 的难点不在生成 SQL，而在 schema 选择与语义歧义。流程：检索相关表/列（数千张表先裁剪到几十张）→ 生成候选 SQL → 语法/权限校验 → 沙箱执行 → 结果自检（为空/异常时改写）→ 返回带解释的结果。

    • schema 检索用表描述 + 列名 + 历史 query 的嵌入；带上主外键与示例值。
    • few-shot 用相似问题的 (question, SQL) 对；方言（Spark/BigQuery）要固定。
    • 安全：只读账号、行级权限、查询超时与扫描量上限。
    • 评估：执行准确率（EX）、结果集匹配、以及人工可用率。
  8. 08

    设计一个会议助手：录音、说话人分离、摘要、待办事项、集成。

    Microsoft
    本站答题要点 + 原文答案

    会议助手 = 采集（多轨音频）→ ASR + 说话人分离 → 对齐与角色归属 → 分段摘要 + 待办抽取 → 与日历/文档/IM 集成。核心挑战是长音频、重叠说话、专有名词，以及“谁承诺了什么”的归属准确性。

    • 多轨（每人一路）比单轨混音好处理；单轨靠 diarization。
    • 摘要分层：先分段摘要，再滚动汇总，避免超长上下文丢失细节。
    • 待办要带 owner + deadline + 原文引用，方便核对。
    • 隐私：录音加密、保留策略、参会人同意、以及区域化存储。
  9. 09

    设计一个 LLM 网关：跨供应商路由、故障转移、缓存、预算与限流。

    PerplexityPalantir腾讯京东2 条原文答案
    本站答题要点 + 原文答案

    LLM 网关负责：统一 API、鉴权与配额、路由（按成本/能力/延迟）、故障转移与重试、语义缓存、限流、成本核算、以及可观测。它是控制面，不承担推理；关键设计是“降级链”和“预算硬上限”。

    • 路由：按任务难度/租户等级选模型；小模型先试，失败再升级。
    • 缓存：精确 hash + 语义缓存，注意租户隔离与失效。
    • 限流：令牌桶按租户/模型/全局三层；超限返回 429 并带 retry-after。
    • 可观测：每请求记录模型、token、成本、延迟、缓存命中、错误码。

    原文答案：LLM 路由 · 语义缓存是如何工作的？

  10. 10

    为面向数亿用户的消费级聊天助手设计服务栈。

    AnthropicOpenAIGoogle DeepMindMetaxAI字节跳动腾讯2 条原文答案
    本站答题要点 + 原文答案

    消费级聊天栈分五层：接入（CDN/网关/WebSocket- SSE）→ 会话与鉴权 → 编排（路由、记忆、安全、工具）→ 推理（多模型池、连续批处理、KV/前缀缓存、P/D 分离）→ 数据（会话存储、向量记忆、分析）。目标是 p99 首 token 与稳定流式。

    • 无状态网关 + 有状态会话存储，便于水平扩展与故障迁移。
    • 推理池按模型分集群，独立扩缩容；热门模型做前缀缓存与预热。
    • 降级：模型过载时切小模型/排队/限制长度，而不是直接 500。
    • 成本：按会话与功能拆分，设置每用户配额与滥用检测。
