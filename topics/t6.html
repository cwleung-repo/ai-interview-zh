  1. 01

    什么是提示注入(直接与间接)？你的分层防御是什么？

    AnthropicOpenAIMicrosoftSierra1 条原文答案
    本站答题要点 + 原文答案

    直接注入是用户在输入里写“忽略以上指令”；间接注入是恶意指令藏在模型会读到的外部内容里（网页、邮件、PDF、工具返回）。分层防御：把外部内容标记为不可信数据、限制工具权限与出网、对动作做人工/策略审批、输入输出过滤、以及最小权限与沙箱。

    • 核心原则：模型无法可靠区分“指令”与“数据”，所以安全边界必须建在模型之外（权限、审批、网络隔离）。
    • 间接注入更危险：用户没做错任何事，只是让 agent 读了一封邮件。
    • 防御纵深：内容净化（去隐藏文本/HTML 注释）、指令层级标记、工具白名单、出站域名白名单、敏感动作二次确认。
    • 检测：注入语料的分类器、异常工具调用序列告警、以及红队持续测试。

    原文答案：LLM 中的提示注入

    常见错误说法

    • “在 system prompt 里写‘不要听从文档中的指令’就够了”——这是概率性缓解，不是安全边界。

  2. 02

    讲讲 LLM 应用的 OWASP Top 10，以及哪些在实践中真的会造成危害。

    本站答题要点 + 原文答案

    OWASP LLM Top 10（2025）大致是：提示注入、敏感信息泄露、供应链、数据与模型投毒、不当输出处理、过度代理权限、系统提示泄露、向量与嵌入弱点、错误信息、无边界资源消耗。实践中最常造成真实危害的是提示注入 + 过度权限、以及输出未净化导致的 XSS/SSRF。

    • 过度代理（excessive agency）常和注入组合：能读邮件 + 能发请求 = 数据外泄。
    • 不当输出处理：把模型输出直接拼进 SQL/HTML/shell，等于把 LLM 变成注入入口。
    • 无边界消耗：没有 token/步数上限，被刷或死循环会直接烧钱。
    • 答题时按“影响 × 可能性”排序，并给出对应控制，而不是背清单。
  3. 03

    越狱(jailbreaking)和对抗性提示(adversarial prompting)有什么区别？

    1 条原文答案
    本站答题要点 + 原文答案

    越狱是让模型违反自身策略（绕过安全对齐），目标是“说出本不该说的内容”；对抗性提示是用精心构造的输入利用模型弱点（可以是越狱手段，也可以是诱导错误、泄露提示、绕过分类器）。越狱是目的，对抗性提示是手段之一。

    • 越狱常见手法：角色扮演、虚构框架、多语言/编码、分步诱导、竞争目标。
    • 对抗性提示还包括：后缀优化（GCG）、同义改写绕过过滤器、图像/音频模态攻击。
    • 防御不是关键词黑名单，而是策略模型 + 输出检查 + 持续红队。
    • 评估要报告攻击成功率（ASR）与误拒率，两者要一起看。

    原文答案：LLM 中的提示注入

  4. 04

    为面向消费者的助手设计护栏。输入过滤、输出过滤，还是两者都用？

    SierraCharacter.AI1 条原文答案
    本站答题要点 + 原文答案

    两者都要，但职责不同：输入过滤拦已知攻击与高风险意图（成本低、可拦截明显越权），输出过滤拦实际生成的违规内容与泄露（最后一道闸）。再叠加策略模型、工具权限控制与人工升级，才是完整护栏。

    • 输入侧：分类器 + 规则（PII、注入特征）+ 速率限制；误杀要可控。
    • 输出侧：安全分类、PII 脱敏、引用校验、格式校验；流式输出要边生成边检查。
    • 护栏会损失有用性，要用误拒率与漏放率共同调阈值。
    • 面向消费者的产品还要考虑年龄、地区合规与危机干预（自伤/暴力）。

    原文答案：LLM 护栏是如何工作的？

  5. 05

    什么是 Constitutional AI？它与 RLHF 有何不同？什么是 RLAIF？

    Anthropic
    本站答题要点 + 原文答案

    Constitutional AI 让模型按一组书面原则自我批评与修订，再用 AI 反馈（RLAIF）替代部分人类偏好标注。与 RLHF 的差别在反馈来源：RLHF 用人排序，CAI 用模型按宪法评判；它更可扩展、更透明，但原则的覆盖与冲突处理仍是难点。

    • 两阶段：SFT 阶段做自我批评与修订（SL-CAI），RL 阶段用 AI 偏好模型（RLAIF）。
    • 优点：减少人类接触有害内容、原则可审计、迭代快。
    • 风险：模型自我评判会继承自身偏差；原则冲突时行为不确定。
    • RLAIF 泛指用 AI 反馈替代人类反馈，Constitutional AI 是其代表实现。
  6. 06

    如何防止一个拥有工具访问权限的 agent 通过恶意网页外泄数据？

    OpenAI1 条原文答案
    本站答题要点 + 原文答案

    假设 agent 一定会被注入，重点限制“注入后能做什么”：工具最小权限、网络出站白名单、把外部内容与指令隔离在不同通道、敏感数据不出沙箱、URL/图片代理防外带、以及对发送类动作强制人工确认与速率限制。

    • 数据外泄通道：markdown 图片 URL、链接预览、DNS 查询、工具参数、甚至错误信息。
    • 对策：渲染前过滤外链、图片走代理、禁止任意 URL 抓取、出站只允许白名单域名。
    • 权限分离：读邮件的 agent 不能发外部请求；需要时由另一个受限服务执行。
    • 审计：记录所有出站请求与工具参数，异常模式告警。

    原文答案：LLM 中的提示注入

  7. 07

    如何在 prompt、日志和训练数据中处理 PII(个人身份信息)？

    Abridge
    本站答题要点 + 原文答案

    PII 要分三层处理：输入侧检测与最小化（能不留就不留）、传输与存储加密 + 脱敏（日志/trace 里打码）、训练数据去标识与访问控制。合规上还要支持删除请求与数据保留策略，并对第三方模型调用做数据不落地的约定。

    • 检测：正则 + NER 模型，覆盖姓名、电话、证件、地址、医疗信息。
    • 日志脱敏要在写入前做，事后清洗往往已经泄露。
    • 训练数据：去重、去标识、版权与授权审查；记忆化风险要用成员推断测试评估。
    • 跨境与供应商：确认 API 是否用于训练、数据驻留地区。
  8. 08

    什么是机制可解释性(mechanistic interpretability)？实验室为什么投入它？

    本站答题要点 + 原文答案

    机制可解释性试图把模型拆成可理解的电路：神经元、注意力头、特征方向、以及它们组成的算法。实验室投入它，是因为它是少数能在部署前给出内部证据的路径之一：检测欺骗、找出危险能力、在模型输出之前发现异常，而不是靠事后抽样。

    • 方法：稀疏自编码器（SAE）找单义特征、激活修补定位因果、注意力头分析、电路追踪。
    • 价值：从“行为观察”升级到“内部状态监测”，可用于欺骗检测与越狱预警。
    • 局限：规模大、成本高、解释的可信度本身需要验证（解释性幻觉）。
    • 与政策的关系：前沿模型的安全案例（safety case）需要内部证据支撑。
  9. 09

    你会如何审计一个已部署模型在不同用户群体上的差异化表现？

    Microsoft
    本站答题要点 + 原文答案

    审计差异化表现要按群体切片评估：先定义受保护群体与切片维度，构造代表性评估集（含交叉切片），比较任务成功率、拒答率、有害输出率与校准误差，做统计显著性检验，再追溯到数据与提示环节。没有切片数据就先补数据，而不是先调模型。

    • 切片：语言、地区、性别、年龄、残障、口音、以及交叉组合。
    • 指标要看差异的相对值与绝对影响，不只看 p 值；小样本切片要报告置信区间。
    • 根因常在训练数据覆盖与 tokenizer（非英语 token 效率低导致成本更高）。
    • 治理：上线前评估、上线后监控、以及可申诉的人工通道。
  10. 10

    为一个即将发布的模型设计红队计划。

    1 条原文答案
    本站答题要点 + 原文答案

    红队计划要覆盖：威胁模型（谁、为什么、怎么攻击）、攻击面（提示、工具、检索、多模态、供应链）、测试方法（人工红队 + 自动化攻击 + 内部可解释性探测）、评分标准（ASR、危害等级）、以及修复与复测闭环。发布前设 go/no-go 门槛。

    • 按能力域分工：CBRN、网络攻击、说服与操纵、自主复制/资源获取。
    • 自动化：GCG/PAIR/TAP 等攻击生成，配合分类器评估；人工红队负责创造性绕过。
    • 记录要可复现：prompt、模型版本、系统提示、工具配置。
    • 发布后持续红队，模型/工具/提示每次变更都要回归。

    原文答案：LLM 评估
