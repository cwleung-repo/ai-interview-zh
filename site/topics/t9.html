    用 NumPy 或 PyTorch 从零实现带因果掩码的缩放点积注意力。

    AnthropicGoogle DeepMindAmazon字节跳动美团滴滴2 条原文答案
    本站答题要点 + 原文答案

    核心是四步：QKᵀ / √d → 加因果 mask（上三角 -inf）→ 按最后一维 softmax → 乘 V。用 PyTorch 的 masked_fill + softmax 即可，注意 dtype 与 mask 的广播形状。

    • mask 要在 softmax 之前加，且用 -inf 或极小值（-1e9），不能用 0。
    • 缩放放在 QKᵀ 之后或预先缩放 Q 都可以，数值上等价。
    • 批量维度：[B, H, T, d]；mask 形状 [T, T] 可广播。
    • 生产环境用 F.scaled_dot_product_attention（FlashAttention 后端），手写只用于理解。
    def attention(q, k, v, causal=True):
    d = q.size(-1)
    s = q @ k.transpose(-2, -1) / math.sqrt(d)   # [B,H,T,T]
    if causal:
        T = q.size(-2)
        mask = torch.triu(torch.ones(T, T, dtype=torch.bool, device=q.device), 1)
        s = s.masked_fill(mask, float('-inf'))
    p = s.softmax(dim=-1)
    return p @ v

    实现多头注意力，然后把它改造成分组查询注意力。

    Google DeepMindMistral AIAlibaba字节跳动美团2 条原文答案
    本站答题要点 + 原文答案

    多头就是把 d 维切成 H 份，各自做注意力再拼接投影。改成 GQA 只需把 K/V 的投影输出改成 H_kv 份，前向时把 K/V 按组 repeat 到 H 份再算注意力，最后仍然拼回 d 维。

    • Q: [B,T,d] → [B,T,H,dh] → [B,H,T,dh]；K/V 同理但头数是 H_kv。
    • repeat_kv：把 [B,H_kv,T,dh] 沿 head 维重复 H/H_kv 次，再与 Q 对齐。
    • 参数量从 4d² 降到 2d² + 2d·H_kv·dh，KV 缓存降到 H_kv/H。
    • 注意 repeat 会复制显存，性能实现里常用 stride/索引而不是真的 repeat。
    q = q_proj(x).view(B, T, H, dh).transpose(1, 2)
k = k_proj(x).view(B, T, Hkv, dh).transpose(1, 2)
k = k.repeat_interleave(H // Hkv, dim=1)   # GQA
out = attention(q, k, v).transpose(1, 2).reshape(B, T, d)

    • 真实实现要处理 block 分配（PagedAttention）、批次内不同长度与抢占。

    从零实现 BPE 的训练与编码。

    1 条原文答案
    本站答题要点 + 原文答案

    训练：统计相邻符号对频次，重复合并最高频对并记录 merge 规则，直到词表达标。编码：把文本拆成初始符号，按 merge 的先后顺序反复应用（用 rank 表贪心合并相邻对）。

    • 初始词表可以是字符，也可以是字节（GPT-2 用字节，保证无 UNK）。
    • 编码时要按 merge rank 从小到大合并，不能按任意顺序。
    • 中文按字节会被拆成 3 个 token，所以中文 BPE 常在字符级训练。
    • 复杂度：朴素实现 O(V·N)；生产用优先队列/heap 优化。
    merges = []
for _ in range(vocab_size - 256):
    pairs = Counter(zip(word, word[1:]))
    (a, b), _ = pairs.most_common(1)[0]
    word = merge(word, a, b); merges.append((a, b))

  5. 05

    在 logits 向量上实现 top-k、top-p 与温度采样。

    Google DeepMindApple2 条原文答案
    本站答题要点 + 原文答案

    温度先缩放 logits（T→0 趋近 argmax），top-k 保留前 k 个，top-p 按概率降序累加到 p 后截断，最后重新归一化并采样。顺序是：温度 → top-k → top-p → softmax 采样。

    • 温度作用在 softmax 之前：logits / T；T<1 更确定，T>1 更随机。
    • top-k 用 torch.topk 把其余置 -inf；top-p 用 cumsum 找最小截断集合。
    • 两者可叠加，但要先过滤再归一化，否则概率和不为 1。
    • 生产里用编译过的 sampler，并支持 per-request 参数与 seed 复现。
    logits = logits / temperature
kth = torch.topk(logits, k).values[..., -1:]
logits = logits.masked_fill(logits < kth, float('-inf'))
probs = logits.softmax(-1)
cum = probs.cumsum(-1)
logits = logits.masked_fill(cum - probs > p, float('-inf'))
next_token = torch.multinomial(logits.softmax(-1), 1)

  6. 06

    实现 O(1) get/put 的 LRU 缓存，然后加上 TTL。

    OpenAIxAIAlibaba
    本站答题要点 + 原文答案

    LRU 用哈希表 + 双向链表：哈希表 O(1) 定位节点，链表头是最新、尾是最旧，get/put 都把节点移到头部，超容量删尾部。加 TTL 就在节点里存过期时间，读取时惰性删除，并定期清理。

    • Python 可以直接用 OrderedDict + move_to_end，但要自己处理 TTL。
    • 并发：单锁最简单，高并发要分片（按 key hash 到多个 LRU）。
    • TTL 过期不等于淘汰：过期项在被访问或清理线程扫到时删除。
    • 面试追问：如何做 LRU-K、LFU、或带权重的淘汰。
    class LRU:
    def __init__(self, cap, ttl):
        self.cap, self.ttl, self.d = cap, ttl, OrderedDict()
    def get(self, k):
        if k not in self.d: return None
        v, exp = self.d[k]
        if exp < now(): self.d.pop(k); return None
        self.d.move_to_end(k); return v
    def put(self, k, v):
        self.d[k] = (v, now() + self.ttl)
        self.d.move_to_end(k)
        if len(self.d) > self.cap: self.d.popitem(last=False)

    实现一个令牌桶限流器，然后让它分布式化。

    AnthropicOpenAIxAICohere
    本站答题要点 + 原文答案

    令牌桶：桶容量 C，按速率 r 补充令牌，请求取 1 个令牌，取不到就拒绝或排队。分布式版把桶状态放 Redis，用 Lua 脚本原子地“按时间差补桶 + 扣减”，避免并发竞态。

    • 允许突发：桶里有积累的令牌时可以短时超速。
    • Redis 实现：key 存 tokens 与 last_ts，Lua 里计算 elapsed×rate，min(C, tokens+…) 后扣减并设过期。
    • 多级限流：租户、用户、全局；用不同 key 前缀。
    • 时钟漂移用 Redis TIME（脚本内取）而不是客户端时间；key 设 TTL；失败时按 fail-open 或 fail-closed 策略决定。
    -- KEYS[1]=bucket, ARGV: rate, cap, cost
local t = redis.call('HMGET', KEYS[1], 'tokens', 'ts')
local now = tonumber(redis.call('TIME')[1])   -- 用服务端时钟，避免客户端漂移
local tokens = tonumber(t[1]) or cap
local ts = tonumber(t[2]) or now
tokens = math.min(cap, tokens + (now - ts) * rate)
if tokens < cost then return 0 end
redis.call('HSET', KEYS[1], 'tokens', tokens - cost, 'ts', now)
redis.call('EXPIRE', KEYS[1], 3600)
return 1

    写一个针对 API 的异步批处理器，支持并发限制、带抖动的重试和错误隔离。

    AnthropicPerplexity
    本站答题要点 + 原文答案

    用 asyncio.Semaphore 限制并发，worker 池消费队列；每个任务包一层重试（指数退避 + 抖动，只重试可重试错误），用 gather(return_exceptions=True) 做错误隔离，最后汇总成功/失败并保证不丢任务。

    • 并发上限用 Semaphore，不要用固定 sleep 控制速率。
    • 重试要区分 429/5xx/超时与 4xx 参数错误；429 要尊重 Retry-After。
    • 抖动避免重试风暴：sleep = min(cap, base·2^n) × random(0.5, 1.5)。
    • 背压：队列有界，生产快于消费时阻塞而不是无限堆内存。
    sem = asyncio.Semaphore(100)
async def call(item):
  async with sem:
    for attempt in range(5):
      try: return await api(item)
      except Retryable as e:
        await asyncio.sleep(min(30, 2**attempt) * random.uniform(.5, 1.5))
    raise
res = await asyncio.gather(*(call(i) for i in items), return_exceptions=True)

    写一个流式 SSE/JSON 解析器，能处理任意分块边界。

    Cohere滴滴京东1 条原文答案
    本站答题要点 + 原文答案

    SSE 解析要维护一个缓冲区：每次 read 追加到 buffer，按 \n\n 切出完整事件，剩下的半截留在 buffer；每行按 field: value 解析，data 行拼接后用 \n 连接，遇到空行派发事件。不要假设一次 read 就是一个事件。

    • 处理 \r\n 与 \n 混用；注释行（以：开头）忽略。
    • JSON 跨块时只在完整事件后 json.loads，否则会解析失败。
    • 要有最大缓冲上限，防止恶意服务端不发分隔符导致内存爆。
    • 流结束时要 flush 最后一个未以空行结尾的事件（按规范可不派发，但要处理）。
    buf = ''
async for chunk in resp.aiter_text():
    buf += chunk
    while '\n\n' in buf:
        raw, buf = buf.split('\n\n', 1)
        data = '\n'.join(l[5:].lstrip() for l in raw.splitlines() if l.startswith('data:'))
        if data and data != '[DONE]': yield json.loads(data)

    实现一个带重叠、且绝不切断语义单元的文本分块器。

    Harvey1 条原文答案
    本站答题要点 + 原文答案

    先按结构边界（标题、段落、列表、代码块）切，再对超长段落按句子切，最后在块之间加重叠。关键是“边界优先级”：语义单元 > 句子 > 字符，绝不从句子/代码块中间切断。

    • 用递归切分：分隔符列表从强到弱（\n\n → \n → 。→ 空格）。
    • 块大小按 token 计（不是字符），因为嵌入模型有 token 上限。
    • 重叠只加在相邻块之间，且不要跨越结构边界。
    • 保留 metadata（来源、标题路径、页码），供引用与过滤。
    def chunk(text, size=500, overlap=50):
    out, cur = [], ""
    for p in split_by_structure(text):      # headings, code, tables
        for s in split_sentences(p):
            if len(cur) + len(s) > size:
                out.append(cur)             # 先落盘完整块
                cur = cur[-overlap:]        # 只保留尾部重叠
            cur += s
    if cur: out.append(cur)
    return out

    在嵌入上实现余弦相似度检索，然后解释为什么你最终不会直接上线它。

    1 条原文答案
    本站答题要点 + 原文答案

    余弦相似度就是归一化点积，排序取 top-k。但它不该直接上线，因为：O(N·d) 暴力扫描撑不住规模、未归一化/维度不同会失真、以及语义相似不等于任务相关（需要 rerank 与业务过滤）。所以生产用 ANN 索引 + hybrid + rerank。

    • 归一化后 cosine = dot，省一次除法；批量用矩阵乘。
    • 暴力检索在百万级就慢了，要 HNSW/IVF。
    • 嵌入模型的训练目标与业务相关性有 gap，纯余弦会召回“像但不有用”的内容。
    • 还要处理：空向量、NaN、维度不一致、多语言混检。
    sims = (Q / Q.norm(dim=-1, keepdim=True)) @ (D / D.norm(dim=-1, keepdim=True)).T
topk = sims.topk(k, dim=-1).indices
