  1. 01

    视觉语言模型如何把图像送进 LLM：投影器、交叉注意力，还是原生 token？

    MetaAlibaba腾讯2 条原文答案
    本站答题要点 + 原文答案

    主流做法是“投影器 + 原生 token”：用视觉编码器（ViT/SigLIP）出 patch 特征，经 MLP/Resampler 投影到 LLM 的词嵌入空间，作为一段视觉 token 拼进序列。交叉注意力的变体（Flamingo）成本更低但生态少；原生 token 方案（LLaVA、Qwen-VL）训练简单、效果最好。

    • 投影器：2 层 MLP 最常见；Q-Former/Resampler 把变长 patch 压成固定数量 query，省 token。
    • 分辨率决定 OCR 与小字能力：切图（tiling）+ 位置编码插值是常见手段。
    • 训练通常分阶段：先冻结 LLM 对齐投影器，再联合微调。
    • token 成本：一张图可能占几百到几千 token，直接影响延迟与价格。

    原文答案：多模态 AI · 解读视觉 Transformer(ViT)

  2. 02

    从图像到视频，会有什么变化？

    Meta字节跳动
    本站答题要点 + 原文答案

    视频多了时间维：帧采样策略（均匀/关键帧/场景切分）、时序位置编码、以及 token 爆炸。常见做法是每帧独立编码后加时间嵌入，或用时空注意力/3D patch；帧数、分辨率和上下文长度三者互相挤压。

    • 关键权衡：帧率 ↑ 时序理解 ↑ 但 token 线性增长；长视频要做层次化摘要或检索。
    • 音频轨是重要信号（说话人、事件），纯视觉会漏掉一半信息。
    • 评估要看时序因果（先后顺序）而不只是单帧描述。
    • 工程：抽帧 + 缩略图 + 关键片段检索，比整段塞进上下文更实用。
  3. 03

    为实时语音 agent 做延迟预算：VAD、ASR、LLM、TTS、网络。时间花在哪里？

    Sarvam AIElevenLabs1 条原文答案
    本站答题要点 + 原文答案

    实时语音的延迟预算通常按端到端 800 ms–1.2 s 设计：VAD 100–200 ms、ASR 150–300 ms（流式部分结果）、LLM 首 token 200–400 ms、TTS 首包 100–200 ms、网络往返 50–150 ms。时间主要花在 LLM 首 token 和 TTS 首包上，所以要做流式与预合成。

    • ASR 用流式部分结果可以提前触发 LLM，但会增加误触发，需要用稳定度阈值。
    • TTS 首包延迟比总时长更影响体感；按句切分流式合成。
    • LLM 侧用短系统提示、限制输出长度、缓存常用回复模板。
    • 要留抖动缓冲，否则网络抖动会造成断音。

  4. 04

    为语音 agent 设计打断(barge-in)处理。

    ElevenLabs1 条原文答案
    本站答题要点 + 原文答案

    打断处理 = 检测 + 停止 + 理解 + 续接：VAD 检测用户开口后立即停止 TTS 播放并取消未完成的合成，把已播放的部分转写进上下文，让 LLM 知道被打断的位置，再基于新输入重新规划。要避免误打断（咳嗽、背景音）和“抢话”失败。

    • 状态机：listening → thinking → speaking → interrupted → listening。
    • 取消要贯穿整条链路：LLM 生成、TTS 合成、音频播放缓冲。
    • 回声消除（AEC）必须做好，否则 agent 会听到自己的声音。
    • 打断后的上下文要标注“用户在第 N 句打断”，否则模型会重复已说内容。

    原文答案：设计一个实时语音 AI Agent

  5. 05

    级联式 ASR+LLM+TTS 与原生语音到语音：请为双方辩护。

    ElevenLabs1 条原文答案
    本站答题要点 + 原文答案

    级联式（ASR→LLM→TTS）可控、可观测、可替换组件，文本中间态便于审核与记忆，但延迟叠加、会丢掉语气与副语言信息；原生语音到语音（SpeechLLM）保留韵律、情感、重叠说话，延迟更低，但训练数据稀缺、可控性差、难以插入工具与安全过滤。

    • 级联式适合企业场景：需要转写、合规审计、工具调用、文本检索。
    • 原生 S2S 适合陪伴、情感交互、低延迟对话，但错误难定位。
    • 混合：原生模型出语义 token，再走文本侧的工具与安全层。
    • 成本：原生音频 token 通常比文本 token 贵得多。

    原文答案：设计一个实时语音 AI Agent

  6. 06

    在没有唯一正确答案的情况下，如何评估 ASR 质量(超越 WER)和 TTS 质量？

    ElevenLabs
    本站答题要点 + 原文答案

    ASR 除了 WER 还要看：实体/数字/专有名词准确率、标点与分段、时间戳对齐、延迟、以及下游任务成功率；TTS 要看自然度（MOS/CMOS）、可懂度（反向 ASR 的 WER）、韵律与情感、说话人相似度、以及流式首包延迟。没有唯一答案时用成对比较 + 人工评分校准自动指标。

    • WER 会被正常化规则操纵（去标点、数字转写），报告时要说明预处理。
    • 领域词表：医疗/法律术语错误代价远高于普通词，要单独统计。
    • TTS 自动指标（UTMOS、SECS）与人工 MOS 相关性有限，关键决策要人工。
    • 端到端：用“语音进、语音出”的任务成功率评估，而不是分段指标。
  7. 07

    在生产 ASR 系统中如何处理语码转换(code-switching)和口音？

    Sarvam AIAbridge
    本站答题要点 + 原文答案

    语码转换和口音的主要问题是训练数据覆盖不足与发音词典缺失。做法：混合语言语料 + 语言边界标注、用多语言模型共享子词、为口音做数据增强与微调、在解码时允许双语词表，并针对口音做分层评估而不是只看平均 WER。

    • 语码转换常发生在实体、数字、专业词上，要保证这些词不被强行翻译或切碎。
    • 口音：重采样、速度扰动、以及真实口音数据（合成数据无法替代）。
    • 评估按口音/语言对分桶，避免平均值掩盖某群体严重退化。
    • 产品侧兜底：允许用户确认/编辑转写结果。
  8. 08

    解释流式 TTS 的分块与抖动缓冲(jitter buffer)大小设置。

    ElevenLabs
    本站答题要点 + 原文答案

    流式 TTS 按句或按语义单元切块合成，块太小会导致韵律断裂、块太大增加首包延迟；抖动缓冲要覆盖网络抖动与解码抖动，通常 100–300 ms，可自适应调整。目标是最小化首包延迟的同时不产生断音。

    • 切块边界优先放在标点/句末，避免在词中间切。
    • 缓冲策略：固定缓冲简单但延迟高；自适应缓冲按到达时间方差调整。
    • 首包优先：先合成短开场白，后续句子并行合成。
    • 监控：underrun（缓冲耗尽）次数与首包延迟的分布。
  9. 09

    设计一个说话人分离(diarisation)系统，并解释如何归属角色，而不只是聚类。

    Abridge
    本站答题要点 + 原文答案

    说话人分离是“谁在什么时候说话”：先做 VAD 分段，再提取说话人嵌入聚类，得到 diarization 结果；角色归属则要把聚类 id 映射到具体角色（医生/患者），靠自我介绍、声纹库、对话结构（谁提问）和业务元数据，而不是只靠聚类。

    • 经典流水线：VAD → 分段 → 嵌入（ECAPA/x-vector）→ 聚类（谱聚类/AGR）→ 重分段。
    • 端到端模型（pyannote、EEND）在重叠语音上更好。
    • 角色归属可用规则 + LLM：谁先说、谁提问、称呼、以及会议参与者列表。
    • 评估用 DER（diarization error rate），角色归属要单独算准确率。

    如何在一个索引中对图像、视频和文本构建多模态检索？

    1 条原文答案
    本站答题要点 + 原文答案

    多模态检索有两种路线：共享嵌入空间（CLIP 类）把图/视频帧/文本映射到同一向量空间，支持跨模态查询；或者为每种模态建独立索引 + 统一的结果融合层。视频要抽帧/切片并保留时间戳，检索结果回到具体片段。

    • 文本查图用 CLIP；图查图用视觉嵌入；视频用帧级 + 片段级两层索引。
    • 混合检索：BM25（OCR 文本、字幕）+ 向量 + 元数据过滤。
    • 结果要能定位：视频时间码、图像区域（bbox）、PDF 页码。
    • 评估用跨模态 recall@k，并单独看罕见实体。
