Perplexity

15 道专属题7 个板块11 道通用题

覆盖岗位

软件工程师(搜索 / 基础设施)、AI 工程师、研究科学家、机器学习工程师(排序与检索)、产品工程师(Comet)。

公开报道的面试流程

招聘官初筛 → 技术筛查 → onsite：一轮 web 规模的检索/排序系统设计、一轮 ML/搜索深挖、一轮实操编码、一轮产品/手艺，以及行为面。对他们自家 App 的产品品味是被明确评估的。

另外还要准备

跨公司通用面试题中标注 Perplexity 的题目，分布在 LLM 内部机制与架构、推理服务与 GPU 性能、RAG 与检索、评估与可观测性、AI 系统设计、编码与数据结构。

这家公司会问的通用题（11）

  • 比较贪婪解码、束搜索、top-k、top-p 与温度采样。各自在什么情况下会失效？
  • 什么是 TTFT、TPOT、ITL 和吞吐？它们之间如何相互权衡？
  • 一次没有改模型的发布之后，p99 延迟翻倍了。请讲讲你的排查思路。
  • 如何在稀疏检索器(BM25)和稠密检索器之间做选择？什么时候两者都需要？
  • 什么是重排序器(reranker)？何时该用它？交叉编码器(cross-encoder)…
  • 当底层语料持续变化时，如何保持索引新鲜？
  • 如何把生成答案中的每一项主张都归因到具体的检索片段？
  • 设计一个 LLM-as-judge 评估。它有哪些已知偏差？如何校正？
  • 设计在线评估：你会记录什么、采样什么、对什么做 A/B？
  • 设计一个 LLM 网关：跨供应商路由、故障转移、缓存、预算与限流。
  • 写一个针对 API 的异步批处理器，支持并发限制、带抖动的重试和错误隔离。
